# src/ — everything the site is built FROM

**Read this if:** you are adding or changing a page, a blog post, a doc, an island, or the styling
of any of them. This is the authored surface; `dist/` and `community/` are outputs.

**Skip if:** you want the deploy (root `README.md` §Deployment — nothing auto-deploys), the
serverless endpoint (`functions/`, NOT `api/`), or hub content (authored in `repos/community`,
copied here at build).

**Below:** `components/` · `content/` · `data/` · `layouts/` · `lib/` · `pages/` · `plugins/` · `stores/` · `styles/`

**Update this file when:** a directory is added or retired under `src/`, or one of the two rules
below stops being true — same commit.

## What's here

| dir | holds | note |
|---|---|---|
| `pages/` | Astro routes — one file or dir per URL | adding a file here adds a public URL |
| `content/` | the Markdown collections: `blog/`, `docs/`, and `config.ts` (their schemas) | a frontmatter field the schema does not declare fails the BUILD, not the page |
| `components/` | `.astro` components, plus `islands/` (hydrated) and `icons/` | `_parked/` is deliberately unused — underscore-prefixed, Astro ignores it |
| `layouts/` | `Layout.astro` (site shell) · `DocsLayout.astro` | |
| `lib/` | build-time helpers — `blog.ts`, `hub.ts`, `icons.ts` | run at build, not in the browser |
| `stores/` | client-side state (`hub.ts`) | ships to the browser; `lib/hub.ts` does not |
| `styles/` | `tincture/` design tokens + two hand-written CSS files | tokens are GENERATED — see below |
| `data/` | `audio-manifest.json`, `soma-version.json` | read at build |
| `plugins/` | one remark plugin (`remark-remove-first-h1`) | why doc pages do not show a duplicate title |

## Two rules that are not obvious from the tree

⚠ **`styles/tincture/_generated` is OUTPUT.** It is regenerated by `pnpm tincture:codegen` from
`registry.json`. Editing a generated file works until the next codegen run silently reverts it —
change the registry instead.

⚠ **`lib/` and `stores/` look interchangeable and are not.** `lib/` runs at build time in Node;
`stores/` is shipped to and executed by the browser. Putting a secret or a Node API in `stores/`
publishes it.
